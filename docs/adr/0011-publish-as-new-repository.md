# ADR 0011：公開のしかた（履歴を含めない新しいリポジトリ）

- 状態：採用（2026-10-21 にオーナーが決めた）
- 日付：2026-10-21

## 状況

このプロジェクトは、非公開のリポジトリで始めた。公開の前に、公開になるものをすべて点検した。対象は、すべてのブランチとコミット、PR の ref、イシューと PR の本文とコメント、本文の編集前の版、Actions のログである。

- 秘密の値と、個人情報は見つからなかった。
- 一方、履歴には、あとで直した記述が残っていた。確かめていない第三者についての書き方や、「主張の書き方」（CLAUDE.md）に合わない文である。いまの本文は直してある。
- 古いコミットは PR の ref からもたどれる。そのため、履歴を書き換えて force push しても、このリポジトリの側からは消しきれない。

## 決定

1. 非公開のリポジトリは、公開に切り替えない。名前を変えて非公開のまま残し、作業を移し終えたらアーカイブする。
2. 同じ名前（`nori1234/pii-token-vault`）で、新しい公開のリポジトリを作る。その時点の main を、1つのコミットにまとめて入れる。
3. GitHub の設定は、中身を入れる前に済ませる。最初の push も push protection で検査させるためである。ルールセットは、最初の push の後に作る（plan 12章）。
4. イシューは、名前と書き方を直したうえで、同じ番号で作り直す。文書の中の「イシュー #N」を、そのまま使えるようにするためである。#1 は、この移行の記録にする。
5. 開発は、新しいリポジトリで続ける。
6. main へのマージは、オーナーが PR ごとに決める。ルールセットでは、承認の件数を求めない（Claude が出す PR もオーナーのアカウントで作られ、作成者は自分の PR を承認できないため。plan 12章）。
7. 外部の人からの PR は受け付ける。CI は、オーナーが差分を読んでから承認して動かす。Claude は、そのブランチを開かない（CONTRIBUTING.md、CLAUDE.md の「進め方」）。

## 結果

- 2026-10-21 より前のコミット、PR、レビュー、Actions のログは、公開のリポジトリにはない。判断の理由は、ADR に残っている。
- 文書の中で、前の経緯を PR の番号で参照していたところは、日付での参照に直した。
- ADR 0010（移行中の参加）は、公開の前には入れない。新しいリポジトリで、イシューと PR として出し直す。番号の 0010 は、そのために空けておく。
- 同じ名前でリポジトリを作り直すので、SECURITY.md と `.github/ISSUE_TEMPLATE/config.yml` の報告先の URL は変わらない。

## 採らなかった案

- **いまのリポジトリを公開に切り替える**：直す前の記述が、履歴に残る。
- **履歴を書き換えてから公開する**：PR の ref が古いコミットを指したまま残るので、消しきれない。
